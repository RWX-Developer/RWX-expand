# 寻路并行求解器 P2（-Drwx.pathing=2）

目标：给「单位寻路跑到地图边缘」这条问题一个可切换的新实现，和旧实现同场 A/B，达标才切默认。

## 1. 为什么不动旧的那 1055 行

旧 `PathSolver` 是 JADX 反编译代码，属 L1（只许安全重构）。新求解器放新文件 `RwxPathSolver2`，
只**读**旧求解器的数据源（`b/c/d` 成本图、`e` 地形组、`f` 净空、`g/h` 尺寸），不改它的内部结构；
旧文件只在 `b()` 加了一行分发。

## 2. 新实现做了什么

- A* 8 向，禁止切角（对角要求两侧正交格可走）；octile 启发式 10/14（可采纳）；
- open 用二叉堆，closed/父指针用 stamp 数组（每条路径不清零整图）；
- 目标策略：目标越界或不可走时，只在半径 4 格内找可达点，**地图最外一圈不当候选**；
  半径内没有就判失败（`endUnreachable=true`，返回空表），不再扫全图找「最近可达点」；
- 预算：单条路径最多扩展 40000 节点，超了判失败，避免烂路径拖住整帧；
- 统计：每 50 条打一行 `RWX_PATH2 solved/snapped/failed/avgExpand`。

## 3. 台架

新增 `-Dbench.path=N`：刷 N 只 `bench:fodder`，每 90 tick 全体 MOVE 到随机点，制造持续寻路。
同机、同图（bench 图 120x120）、每次 100 秒墙钟。

## 4. 实测（单次，2026-11-21）

| 指标 | 旧 `-Drwx.pathing=1` | 新 `-Drwx.pathing=2` |
| --- | --- | --- |
| pathing 平均 | 0.07 ms | 0.06 ms |
| pathing 峰值 | **3.5 ms** | **1.3 ms** |
| 到达 tick | 4200 | 3600 |
| 旧求解器统计行 | 949（每 100 条一行） | — |
| 新求解器统计 | — | solved=2000 次调用、snapped=1、failed=2331、avgExpand=1118 |
| FAKEEND 放弃 | 20 条（日志上限） | 0 |
| 边缘路径 RWX_EDGE_PATH | 0 | 0 |

解读：

- 峰值寻路耗时降到 1.3 ms（旧 3.5 ms），尖峰明显收敛；平均值两者接近（该场景路径本身短）。
- 旧实现的「假终点」会挑最近可达点、常常是边界格；新实现把边界环排除出候选，越界/不可达目标直接失败。
- 失败比例高（2331/4331 次调用）：台架把目标点撒到图外/不可走区，这正是旧实现「走到边界停住」的来源；
  新实现让这些命令直接无效，不再有位移。**这是行为变化，不是 bug**，但需要局内确认玩家观感（部队不动 vs 走一半）。

## 5. 未做 / 风险

- `DynamicUnitPath`（流场，`OrderableUnit.L=true` 时启用）仍走旧 `f()`，新实现只覆盖点对点路径；
  本版本 `L=false`，实测走了新路径，但一旦开启流场就绕开新实现。
- 旧回放：寻路结果变化会改重演结果，切默认前要考虑版本标记。
- 单次测量、未做 3 次中位数；下一步补重复性。
