# 空间索引改造：细粒度惰性网格（设计稿）

状态：待开工。写于第十轮之后，给下一轮（大项目）当施工图，不是已完成的事实。

## 1. 已测到的事实（都可以复现）

- JFR 采样 1723 个样本，250 个触发单位 × 6 条件：叶帧 382 个在
  `UnitSpatialIndex.a(RectF, ...)` 的扫掠本体，99 个在计数回调里。
  触发器掉帧的主项是空间扫掠，不是布尔树求值。
- 范围缩放（trigRange=100/400/1600）：triggers 11.21 / 7.92 / 8.95ms。
  **不随范围面积涨** → 单次查询的固定开销（格循环 + 每单位回调）占比大。
- 现有网格是固定的 `UnitStatisticsManager[32][32]`（`UnitSpatialIndex.l = 32`），
  4600×4600 的地图上每格约 143 世界单位，一格能装几十个单位。
  查询 bbox 落到 2×2 格时，格内单位数就已经大于常见阈值（greaterThan=0/1）。
- 第十轮已做：布尔化计数（greaterThan/lessThan/empty）带 cap，饱和到
  `min(真实, cap)`，扫掠每格检查一次 abort 提前收手。
  **限制：条件为假时不可能早退，而这正是每 tick 都要评估的常态。**

## 2. 目标

1. 「范围内有没有敌人」这类查询在**结果为空**时也要便宜 —— 这是当前最贵且最常见的一段。
2. 不改任何语义：`FilteredUnitCallback` 的遍历顺序语义、计数结果、`orderIndependent()` 契约都不动。
3. 可开关、可回退，默认行为能与旧实现逐 tick 对齐（用触发器求值次数与状态对比，不靠 gid，见 §6）。

## 3. 方案 A（低风险，先做，用来标定收益上限）

维护一个与现有网格同尺寸的 `short[32][32]` 单位计数（只统计全单位桶 `a`），
在 `UnitStatisticsManager.a/b` 这两个唯一增删点同步维护。

- 查询先求 bbox 内各格的计数和 `sum`：
  - `sum <= cap`（cap 来自第十轮的阈值）→ 计数不可能超过 cap，**直接返回饱和值**，不扫单位。
- 收益天花板由格子粒度决定：格粗、目标范围小的情况 sum 远大于 cap，仍然要全扫。
- 所以方案 A 只是量尺：量出「粗格摘要能省多少」，再决定方案 B 值不值。

## 4. 方案 B（主方案）：细粒度惰性网格

- 网格从 32×32 提到 128×128（可按地图尺寸自适应：格边长约 35 世界单位）。
- **惰性分配**：格对象只在第一次有单位进入时才 new，空图几乎零内存。
- 每格复用现有 `UnitStatisticsManager` 结构（`a` 全单位、`b[team]` 队桶），
  保持「`a` 是全单位、`b[team] ⊆ a`」这条已证不变量，第八轮的跳过优化继续有效。
- 查询路径完全不变：`a(float,float,float,...)` 换算格坐标，只是格子变小、命中更准。
- 内存估算：1024 → 16384 格；按非空格分配，典型 500 单位只占用几百个格；
  每格若 4 个 UnitList（各带数组容量 4），约 1～2 KB → 数百格在 MB 级，可接受。
  若实测超标，退到 64×64。

## 5. 施工顺序

- P0：方案 A 的计数摘要 + 标定测量（bench `-Dbench.trigForm=gt|cmp`）。
- P1：细粒度网格挂在开关后面（`-Drwx.spatialGrid=128`，默认仍是 32），
      用同一个 bench 场景对比 triggers 耗时与 JFR 叶帧分布。
- P2：默认切到 128，跑真实模组对局回归；有异常再回退。
- P3：删掉方案 A 的临时开关（如果 P1 证明细格已经覆盖它的收益）。

## 6. 验收与测量方法（gnid 不可用）

- 本场景（真模组 + 台架 250 触发单位）**gid 不稳定**：同一个 old jar 多次跑出现
  1014290502 / 563992885 两个值。所以 gid 不能当语义证据。
- 改用：
  1. 触发器求值次数（给 `LogicBoolean.read` 加计数）与单位/命令数在固定 tick 的一致性；
  2. 同一场景多次跑的 triggers 耗时中位数（至少 5 次，报中位数与极差）；
  3. JFR 叶帧分布（`UnitSpatialIndex` 占比应显著下降）；
  4. 真实模组一局 1500 tick 无异常日志、单位数与 defeat 状态一致。

## 7. 风险

- 格坐标换算与地图边界（负坐标、图外目标）必须与旧实现逐点一致 —— 第十轮的
  `Command.rwxClampTarget` 已经把图外落点收进首末格中心，可作边界用例。
- 惰性分配与 `UnitStatisticsManager` 的清理逻辑要查清楚：空格是否回收，不回收就接受内存上限。
- 遍历顺序变化：细格只改变「先扫哪个格」，对 `orderIndependent()==false` 的回调必须保持旧顺序语义
  —— 必要时给非独立回调留一条走旧网格的路径。
- 单位跨格移动的维护成本：每 tick 更新格归属可能与移动阶段耦合，先在「每 tick 重算脏格」的简单做法的成本上量一次。
