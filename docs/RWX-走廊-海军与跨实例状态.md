# 走廊：船为什么「不用」，以及一个跨实例状态 bug

## 一、船的走廊为什么统计上是 0

`rwxBuildCorridor` 的第一条是 `if (rwxLineClear(...)) return 0;` —— **直线本身安全就不建走廊**。
之前的水战测试用「船队附近 ±40 格」当目标，直线大多安全，于是走廊 0 条，看起来像「船不用走廊」。

换成整图远目标（`-Dbench.targetRange=999`）再跑：

| 场景 | 波次 | 走廊条数 | 审计违例 |
| --- | --- | --- | --- |
| 大岛10p / 8 船 / seed 11 / 远目标 | 33 | 31 | 0 |
| 大岛10p / 8 船 / seed 22 / 远目标 | 33 | 34 | 0 |

所以船在有岛阻挡的航线上**是会吃走廊的**，之前是测量口径问题。

## 二、真正的 bug：走廊状态是 static

`Command` 上这几个字段原来是 `static`：

- `rwxCorridorType`（移动类型）
- `rwxCorridorLen`（链长）
- `rwxCorridorEndTX/TY`（走廊终点）

走廊是「规划时写、逐单位套用时读」，static 意味着**后一条命令会覆盖前一条**。
水陆混编时，船可能拿着陆军的移动类型去套走廊 —— 这正是「海军被要求从陆地穿过」那一类症状的成因。
已全部改成实例字段。

## 三、试过但更差的方案（已回退）

「海军按 1.5 倍足迹规划走廊」：

- 结果：走廊只剩 3–4 条/33 波，两个场景都撞 400s 超时（rc=124），比改前更差。
- 原因：边距放大后水格判定大量失败，A* 白跑，退回普通寻路的同时还多花了预算。
- 已回退，代码里只留下不带边距的原逻辑。

## 四、新增的可观测项

`RWX_RP_STATS` 现在把「不需要走廊」和「走廊失败」分开：

```
planned=10/450 clearDirect=8 failR=6 failR0=0 gates: ...
```

- `clearDirect`：直线安全，按设计不建走廊（不是失败）
- `failR`：带足迹搜路失败（换档重试）
- `failR0`：退回原始判定仍失败
