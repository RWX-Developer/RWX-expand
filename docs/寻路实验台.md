# 寻路实验台（完全隔离）

不启动游戏，直接喂真实代价网格，跑**游戏里那份** `RwxAStar.java`（原样拷入，不改）。
目录：`tools/pathlab/`

## 怎么跑

```bash
# 批量：300 组随机起终点，出统计
bash tools/pathlab/run.sh

# 单例：起点 40,180 -> 终点 200,60
bash tools/pathlab/run.sh 40 180 200 60
```

输出：`tools/pathlab/out/worst.ppm`（最差偏离案例）、`out/path.ppm`（单例）。
灰度 = 可走格，深色 = 不可走，红 = 路径，绿 = 起点，蓝 = 终点。

## 数据

`data/cost-LAND.csv`：从运行中的游戏导出的陆军代价图，Crossing Large (10p)，230×230。
-2 = 不可走，其余 = 该格代价。来源 `docs/images/rwx-grid-cost-LAND.csv`。

## 首次实测（2026-11-23）

```
cases=300 ok=226 fail_unreachable=63 fail_astar=11
avgNodes=111 borderHitsTotal=56 pairsEndNearBorder=34
worstDeviation=72.5 case=183,208 -> 205,38
```

结论：
1. **A* 不贴边界**。226 条成功路径里共 56 个贴边航点，全部来自「起终点本身就在边界附近」的 34 组。
   内点之间的路径贴边数为 0。
2. **11/300 在可达情况下 A* 放弃**（MAX_EXPAND=6000 太小），这是真 bug。
3. **最差偏离 72.5 格是地形导致的合理绕行**（两端被大片水域隔开），不是算法走歪。
   → 说明「偏离起点-终点连线超过 3 格就删航点」这条规则会误删正确路径点。
4. 平均 111 个航点 = 逐格一个点，和引擎原路径一致。

## 边界

- 只测了陆军（LAND）代价图，海军/悬浮/飞行没测。
- 代价全部为 0（这张图没有代价>0 的地形），所以 COST_SCALE 加权效果测不出来。
- 实验台不含 `PathSolver.e()/g()` 的扫描逻辑，只测 A* 本体。

## 第二轮：陆地 / 海军 / 悬浮 × 六张合成地形（含岩浆、水桥）

地形码：0 平地 / 1 林地 / 2 沼泽 / 3 水面 / 4 水桥 / 5 岩浆 / 6 悬崖。
换算（10 = 多走 1 步）：

| 移动类型 | 平地 | 林地 | 沼泽 | 水面 | 水桥 | 岩浆 | 悬崖 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| LAND | 0 | 2 | 6 | 走不了 | 0 | 走不了 | 走不了 |
| WATER | 走不了 | 走不了 | 走不了 | 0 | 0 | 走不了 | 走不了 |
| HOVER | 0 | 1 | 3 | 0 | 0 | 走不了 | 走不了 |

实测（每格 100 组随机起终点，同图同种子）：

| 地图 / 类型 | 有效组数 | 成功 | 平均代价 | 代价盲选基线 |
| --- | --- | --- | --- | --- |
| roads / LAND | 100 | 100 | 47 | 166 |
| roads / HOVER | 100 | 100 | 22 | 73 |
| swampfield / LAND | 100 | 100 | 21 | 316 |
| swampfield / HOVER | 100 | 100 | 16 | 157 |
| river / LAND | 100 | 100 | 42 | 89 |
| river / WATER | 47 | 47 | 0 | 0 |
| river / HOVER | 100 | 100 | 17 | 42 |
| lava / LAND | 100 | 100 | 255 | 351 |
| lava / HOVER | 100 | 100 | 136 | 176 |
| lava / WATER | 9 | 9 | 0 | 0（水域只有 159 格） |
| archipelago / LAND | 25 | 25 | 0 | 0（陆地只有 5214 格） |
| archipelago / WATER | 100 | 100 | 0 | 0 |

结论：
1. 六张图 × 三种移动类型，`fail_astar` 全部为 **0**（上限 60000 之后）。
2. 代价感知在陆地/悬浮上都成立：路网 47 对 166、沼泽棋盘 21 对 316、岩浆图 255 对 351。
3. 海军在只有一条河的地图上根本跑不开（最大连通块 1467 格），要测海军得用群岛那种水占多数的图。
4. 水桥对 LAND 和 WATER 都可走，实测悬浮在岩浆图上正是从水桥那列穿过岩浆带。

注意：`roads`/`canyon`/`swampfield` 三张图**没有水面**，所以 WATER 的有效组数是 0，不是失败。

## 第三轮：真实地图的 8 张代价图（游戏内导出）

从运行中的进程导了全部 8 张 PathCostMap（160×160，当前加载的那张图）：

| 移动类型 | 不可走格数 | 占比 |
| --- | --- | --- |
| NONE | 564 | 2.2% |
| LAND | 18588 | 72.6% |
| BUILDING | 18683 | 73.0% |
| WATER | 8537 | 33.3% |
| AIR | 0 | 0% |
| HOVER | 713 | 2.8% |
| OVER_CLIFF | 17623 | 68.8% |
| OVER_CLIFF_WATER | 560 | 2.2% |

A* 在真图上的表现（每类 300 组随机可达起终点）：

| 类型 | 成功 | 真不可达 | A* 放弃 | 平均航点 | 内点路径贴边数 |
| --- | --- | --- | --- | --- | --- |
| LAND | 295 | 5 | 0 | 60 | 0 / 295 条 |
| WATER | 300 | 0 | 0 | 109 | 0 / 233 条 |
| HOVER | 300 | 0 | 0 | 72 | 0 / 256 条 |
| AIR | 300 | 0 | 0 | 71 | 0 / 258 条 |

**关键结论**：两端都不靠边的路径，贴边界航点数**全部是 0**。
WATER/HOVER/AIR 的那些贴边航点（274/220/232）全部出现在「起点或终点本身就在地图边缘」的组里。
→ 游戏里“单位跑到边界”的问题**不在 A\* 里**，要往引擎给路径点的地方找（直线捷径 / PathSolver.g() / 命令坐标钳制）。
