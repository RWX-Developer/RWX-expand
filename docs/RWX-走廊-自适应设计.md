# 走廊的自适应设计（体积 / 距离 / 起终点 / 阻挡）

老师给的设计口径：**走廊按单位体积、到目的地的远近、自身坐标与目的地坐标、阻挡计算来定；路线以单位或一群单位为中心。**

## 落地的四条

1. **体积**：取这一群里所有存活单位的**最大半径**，不再只看排头兵。
   多单位混编时，宽的那个决定走廊宽度。
2. **距离**：路线长度（起终点世界距离换算成格）参与安全边距，
   `rpx = maxRadius × (1.15 + min(0.45, 路线格数 / 240))`。
   路越长，沿线蹭岸的累计误差越大，边距就多留一点；短路不多花代价。
3. **起终点**：起点用队形中心（成队时）或单位坐标（单发时），终点用吸附后的可通行格；
   两者都由世界坐标换算到格，避免坐标系混用。
4. **阻挡**：A* 在格网格上搜，节点判定用「圆足迹 vs 障碍格距离」，不按整格膨胀；
   斜向移动要求两个相邻格都放得下（不切角）。

## 预算也跟着距离走

| 路线长度 | 节点预算 | 时间预算 |
| --- | --- | --- |
| 短路 | 12000 | 8 ms |
| 长路（约 750 格） | 90000 | 24 ms |

原来是固定 60000 节点 / 16 ms，短路浪费、长路不够。

## 实测（Many Islands Large 350×350，8 船，远目标）

| 场景 | 波次 | 走廊 | 审计违例 |
| --- | --- | --- | --- |
| seed 11 | 4 | 5 | 0 |
| seed 22 | 4 | 4 | 0 |

日志里能看到边距确实按距离变：

```
3,4 -> 225,89  r=22px len=271   （长路，边距放大）
21,77 -> 28,55 r=15px len=24    （短路，基本足迹）
```

## 怎么验

```
java -Drwx.selftest=1 -Dbench.water=8 -Dbench.targetRange=999 -Dbench.waveTicks=600 \
  -Drwx.selftest=1 -jar RWX-windows-x64-1.1.4.jar --headless "--map=maps/skirmish/[z;p10]Many Islands Large (10p).tmx" --ticks=3000
```

看 `RWX_RP corridor ... r=.. len=..` 与 `RWX_PATH_AUDIT`（必须为 0）。
