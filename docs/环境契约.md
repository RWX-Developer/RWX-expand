## 2. 硬规则

1. **不在游戏运行时改包**：RWX.exe 或 java.exe 在跑时禁止覆盖 jar（会被锁 / 写坏）。部署脚本会拦。
2. **部署必须备份 + 原子替换**：先备份到 logs-archive，再 cp 到临时名 + mv。禁止就地覆盖。
3. **每次部署后校验**：文件大小 + md5 都要打印出来，写进 CHANGED-FILES.txt。
4. **推送前先探代理**：`curl 127.0.0.1:18099` 不通就先起 `D:/Game/tools/github-pin-proxy.js`。
5. **测性能必须重复**：单次跑出来的数字不当结论，至少 3 次报中位数；本场景 gid 不稳定，不能当语义证据。
6. **CRLF 纪律**：源码是 CRLF，多行改动要断言括号平衡，改完看 diff。
7. **反编译文件默认只做 L1 重构**：改名/提常量可以，控制流改写必须台架 A/B。
8. **大文件先抽接缝**：5,000 行级文件不就地魔改。
9. **删东西要问**：logs-archive、backups、源码树，不擅自清理。

## 3. 脚本（env 化，省掉手敲）

| 脚本 | 用途 |
| --- | --- |
| `scripts/env-check.sh` | 体检：磁盘/内存/代理/进程/git/缓存/备份。只读。 |
| `scripts/build.sh [任务...]` | 固定 JAVA_HOME，默认构建客户端 jar + 台架模组，打印耗时与失败行 |
| `scripts/deploy-pack.sh [目录]` | 查进程、备份、原子替换、打印 size+md5 |
| `scripts/bench.sh [-Dbench.*]` | 台架重复 N 次报中位数，自动备份/还原 preferences |
